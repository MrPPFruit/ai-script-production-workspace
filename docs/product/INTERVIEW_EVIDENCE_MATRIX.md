| 候选设计 | 理由 | 条件/风险 |

### 不可从录音得出的结论

- 必须使用 React/Flutter、无限画布、列表页或任何特定视觉布局。
- 必须接入真实项目管理、通知、手机端、权限、预算或排期系统。
- 完整实体 schema、分类树、部门映射、命名/编号规则及 Metadata 必填规则。
- “原文明确/生产推断”、编辑/确认/拒绝/合并等具体状态和文案。
- 自动识别 VFX、自动创建实体、自动派发任务或自动继承版本关系。
- 任务已下发后的更新、撤回、回执、人员负荷或生产排期处理。
- 本题是否应有 Agent，或任一组件是否有资格被称为 Agent。

## 制片统筹的最小工作流（建议，不是已冻结规格）

```text
输入剧本与场次
  → 在预置实体体系内得到 AI/模拟建议
  → 制片统筹调整并决定哪些生产信息可用
  → 建立带 Metadata、来源和关联的实体
  → 按部门/主管组织“做什么、相关场次与剧本语境、何时需要”的任务材料
  → 剧本变更时，先查看场次与实体关联受何影响，再由人决定如何处理
```

| 工作流要素 | 录音支持 | 必须避免 |
| --- | --- | --- |
| 输入 | 剧本、场次、剧本内容（E-03、E-04）。 | 只输入孤立文本，丢失场次与工程语境。 |
| AI 建议 | 可调用或模拟 AI（E-17），但不能随机抓取（E-12）。 | 把自由生成当系统记录，导致类别/数据不可控。 |
| 人审 | “能方便调整”（E-03）明确支持。 | 擅自把确认、拒绝、合并当作录音规定的完整流程。 |
| 实体与 Metadata | 明确支持（E-04、E-14）。 | 把实体简化为名字或视觉标签。 |
| 部门任务 | 明确支持实体→任务、部门主管与准备窗口（E-03、E-05、E-15）。 | 只展示部门名而不给任务上下文；或声称已解决真实派单。 |
| 版本变化 | 明确支持场次/实体关联继承的问题（E-06）。 | 静默覆盖旧关联，或承诺已下发任务的自动更新。 |
| 下游接收者 | 制作人员/部门主管接收具象实体及当前任务相关 Metadata（E-14、E-15）。 | 要求接收者阅读全剧本或给其没有来源的抽象标签。 |

## 需要用户确认的最少五项决策

1. **MVP 实体体系：**是否先用角色、场景、道具、VFX 四类；场次、镜头是实体还是仅作为输入/关联？
2. **人审边界：**Demo 只需“调整后创建实体”，还是要显式展示确认、拒绝、合并等完整状态？
3. **任务边界：**Demo 是否止于面向部门主管的“任务材料/草稿”，不模拟真实已下发状态？
4. **版本案例：**是否接受仅演示一次“场次插入/切分 → 实体关联受影响 → 人工处理”，不承诺自动继承算法？
5. **AI/Agent 叙事：**是否将 AI 仅说成“受规范的建议来源”，不在本题主张或讨论 Agent；若要讨论，需另定其工具与写入权限边界？
