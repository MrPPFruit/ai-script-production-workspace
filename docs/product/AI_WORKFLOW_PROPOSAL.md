# AI Workflow 方案：《雷雨》第四幕批处理进入人工审阅

> 状态：**能力合同已确认，具体 UI 待确认**
> 已确认：DeepSeek 真实 API 是正式 Demo 主链；第四幕导入全文常驻；3–4 个处理单元顺序执行；精确 evidence 高亮；AI 结果必须经过 HITL。
> 待确认：新增控件的具体文案、位置、确认层和视觉布局。本文不授权 UI 实现。

## 1. 唯一用户结果

制片统筹在《雷雨》·面试 Demo 导入版本（第四幕）中发起一次真实 DeepSeek 分析，看到 3–4 个处理单元的诚实进度，并把结构与原文证据合格的建议送入人工审阅，最终形成稳定实体和未下发部门任务草稿。

“完整文本”只指第四幕本次导入全文。处理单元不是原作场次，只是单次 API 的执行与失败隔离边界。每条建议的真正来源粒度是精确 quote/range。

## 2. 当前实现事实

- 服务端单次 API、DeepSeek 调用、结构/evidence 校验和 mode/reason 已存在。
- 客户端 requestBreakdown 和顺序 processVersionScenes 已存在。
- 当前 App 尚未接线；orchestrator 只保留 suggestionCount，没有完整建议载荷。
- 《雷雨》第四幕私有/本地导入数据、3–4 个处理单元、全文锚点和精确 evidence 映射尚未实现。
- 当前 fallback 只有通用单条建议，尚未按处理单元复用确定性数据。
- AiRun/SuggestionBatch 历史、重新分析和版本影响新案例尚未实现。

因此，API 和库函数存在不等于用户主链完成。

## 3. 用户可见处理链

> 准备处理单元队列 → 当前单元请求 DeepSeek → 服务端结构/证据校验 → deepseek 或 fallback 待审 → 下一单元 → 全部进入人工审阅

| 用户可见状态 | 可证明事实 |
| --- | --- |
| 等待处理 | 该单元尚未请求 |
| 正在请求 DeepSeek | 当前请求尚未返回 |
| DeepSeek · 已校验 · 待审 | mode=deepseek，服务端校验已完成 |
| 演示数据 · 待审 | mode=fallback，并显示原因 |
| 请求失败 | 没有安全合格响应 |

不得伪造“正在识别角色”“正在分析道具”等模型内部阶段。

## 4. 全文与 evidence 联动

- 中间阅读区始终显示第四幕导入全文。
- 处理单元导航只滚动到锚点，不用单元文本替换全文。
- 点击建议/evidence 会切换到建议所属版本、滚动并高亮精确 quote。
- 服务端校验处理单元内 range，客户端映射为第四幕全文 range。
- 点击证据不触发新 AI，也不改变人审或实体状态。

## 5. DeepSeek、fallback 与兼容边界

- 正式 Demo 在服务端配置 DeepSeek，逐处理单元顺序调用。
- 全部完成后显示实际单元数、deepseek/fallback 数和待审建议数。
- fallback 必须展示原因并使用本单元确定性建议，不能冒充模型成功。
- 不做隐藏重试；重新分析由用户显式触发并新建批次。
- 现有 sceneId/title/text 继续作为内部兼容字段；产品层映射为 analysisUnitId/title/text，并保留 sourceSection=第四幕，不要求本次重构 API。

## 6. HITL 与生产写入

AI 只能建议 taxonomy、名称、制作说明、证据、置信度和可选既有实体候选。只有人工可以编辑、采用为新实体、关联既有实体或忽略。

文本片段不会直接变成实体。ProductionEntity 使用稳定 ID，并通过关系保存第四幕、处理单元和精确 evidence 来源。TaskMaterialDraft 只从人工确认实体生成，保存来源快照并明确未下发。

## 7. 重新分析与版本

- 重新分析当前单元或全部单元只新增 AiRun/SuggestionBatch。
- 旧批次、人工决定、实体和任务草稿不被覆盖。
- 版本演示只做一次处理单元插入/切分后的来源关系人工复核。
- 不宣称通用自动继承、自动 diff 或原作场次重建。

## 8. 最小 UI 组合（待确认）

1. 第四幕导入全文阅读区；
2. 3–4 个处理单元导航与状态；
3. “分析全部处理单元”主入口和发送/HITL 边界说明；
4. run 摘要；
5. 可定位全文 evidence 的建议卡片；
6. 编辑、采用新实体、关联既有、忽略；
7. 实体与未下发部门任务草稿；
8. 一次版本影响复核；
9. 静态产品边界，不放死按钮。

## 9. 路线图

- 自动处理单元拆分；
- 镜头级拆分；
- 任意剧本的生产级导入和批处理；
- 通用 diff 与自动关系继承；
- 真实任务派发、更新、撤回；
- 多用户协作、模型质量评测和 Prompt 运营。
