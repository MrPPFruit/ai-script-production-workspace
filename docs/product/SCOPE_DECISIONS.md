## 2. 录音证据边界

录音明确支持场次、镜头、道具等生产要素可调整、建实体和挂 Metadata，并以“10 场变 11 场”举例说明插入/切分影响。录音没有规定拆分算法、固定数量、镜头级必须实现或通用自动继承。

因此，3–4 个处理单元是本 Demo 的实现选择，不是原作结构或录音硬要求；镜头级拆分不进入 MVP；版本能力只验证一次处理单元插入/切分后的人工关系复核。

## 4. 状态与写入边界

> 准备处理单元队列 → 当前单元请求 DeepSeek → 服务端结构/证据校验 → deepseek/fallback 待审

- UI 只显示等待、请求中、DeepSeek 已校验待审、fallback 待审或失败。
- 内部 scene 字段不得在 UI 被解释为原作场次。
- evidence.quote 必须是处理单元文本逐字子串，并映射到第四幕导入全文。
- 点击建议只改变阅读位置和高亮，不触发新 AI 或生产写入。
- AI 不得创建/覆盖实体、关系、任务、版本、负责人、截止日或预算。
- 人工采用/关联/忽略是唯一写入边界。
- TaskMaterialDraft 永远不是已送达任务。
- 任务标题、制作要求、部门、优先级和材料成熟度可以人工调整；来源、版本与“未下发”不可编辑。
- 重新分析和单元插入/切分不得原地改写旧批次、实体或草稿。

## 5. 已解决与仍开放

已解决：默认剧本和标题、第四幕导入全文的含义、3–4 个处理单元、精确 evidence、镜头级非目标、一次版本案例和版权非阻塞边界。

仍开放但不阻塞文档收口：

- 公开 GitHub 是否最终包含正文由交付阶段单独决策；当前默认不提交正文。
- 类型筛选、中文映射和版本化编辑说明入口仍待最终集成验收。

## 6. 路线图

- 自动处理单元拆分算法；
- 镜头级拆分；
- 任意长剧本的生产级批处理；
- 通用自动分场、通用 diff 和自动关系继承；
- 完整剧本编辑提案、新 ScriptVersion、diff、受影响单元重分析与选中文字触发新 AI；本轮仅保留正确流程说明；
- 真实任务派发、更新、撤回、通知和回执；
- 多用户、模型质量评测、Prompt 优化、预算和完整项目管理。

## 7. AIWF Acceptance

AIWF-01 至 AIWF-10 是稳定 Acceptance ID。定义、Owner、Observable、Counterexample 与 Evidence 以 PRODUCT_SPEC、AI_WORKFLOW_PROPOSAL 和 OpenSpec Delivery Contract 为准；不能以 API 存在、构建通过或单元数量单独替代用户结果。
