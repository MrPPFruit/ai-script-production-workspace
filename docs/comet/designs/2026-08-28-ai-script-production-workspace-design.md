# AI 剧本生产工作台技术设计

## 实现决策

- 单页应用使用 React、Vite 与 TypeScript；`App` 只负责组合，审阅、实体任务和版本影响分别拥有组件与状态模块。
- 领域状态以确定性种子数据启动；所有交互都走与真实分析结果相同的类型和转换函数，不为 Demo 另写一套静态页面。
- 模型输出先在服务端转换为固定 taxonomy 与领域 schema，只有通过校验的建议才能进入客户端审阅状态。
- DeepSeek 请求由 `/api/ai/breakdown` 代理并只读取服务端环境变量；失败回退必须返回可识别的 `mode: mock`，前端据此披露模式。
- 实体持有稳定 ID 和多场次关系；任务草稿持有实体引用及创建时的剧本版本/需求快照，避免后续源变更无声污染任务。
- V2 仅生成影响集合和人工决策，不实现自动 diff 继承；该边界同时作为演示内容和回滚保障。
- 视觉实现必须等待三套完整主屏概念选定，并从选定图提取 token、可见文案、组件家族与容器模型。

## 依赖与边界

- 运行时依赖保持小型化；不引入数据库、认证、状态服务或完整项目管理后端。
- 公网托管需要同时支持静态前端与服务端 API；具体平台在部署阶段按可用凭证选择，默认优先 Vercel。
- 模型供应商不可用不会阻断核心产品链，但不能把 mock 结果伪装为实时模型结果。

## 主要风险

- 模型结构漂移：服务端 schema 校验、超时和确定性回退。
- 公开凭证暴露：环境变量、Git/构建产物扫描、日志脱敏。
- 多栏界面拥挤：锁定桌面主视口并验证窄屏不裁切；不把 Demo 范围扩成完整移动产品。
- 概念与实现漂移：概念/截图同尺寸对比，逐项修复文案、布局、字体、颜色、间距、图标和交互状态。

## 测试 Seam

- 纯函数测试：建议状态转换、实体合并、任务快照和版本影响决策。
- API 契约测试：无密钥、超时、供应商错误、无效 schema 和有效结果。
- 浏览器真链：定位证据、编辑/确认、跨场次合并、生成部门任务、处理一条 V2 影响。
- 交付验证：lint、类型、测试、构建、秘密扫描、前端产物扫描、公网访问与公网真链。

## 回滚与非目标

- 移除服务端密钥即可回到 mock 模式；静态核心链不受影响。
- 不实现登录、多租户、数据库、真实通知、预算、完整排期、模型评测和生产级版本迁移。

## Acceptance Design

- [AIR-01] Owner: 建议审阅状态；Observable: 用户从建议定位证据并完成校订；Counterexample: 静态卡片或操作后状态不变；Evidence: 浏览器审阅真链。
- [AIR-02] Owner: 实体与任务状态；Observable: 跨场次稳定实体生成部门任务快照；Counterexample: 重复卡片或无下游引用；Evidence: 浏览器实体到任务真链和领域测试。
- [AIR-03] Owner: 版本影响集合；Observable: V2 影响等待人工决策且不改写任务；Counterexample: 仅显示版本号或静默覆盖；Evidence: 浏览器影响决策和状态测试。
- [AIR-04] Owner: 服务端 AI 边界与交付面；Observable: 公网可用、模式真实、凭证不可达客户端；Counterexample: 只在本地通过或秘密进入仓库/产物；Evidence: 公网真链、秘密扫描和产物检查。
