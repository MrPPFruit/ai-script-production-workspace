# 《雷雨》第四幕默认样本导入 QA

复核日期：2026-08-28。环境：本地 Vite，桌面默认视口与 390 × 844 窄屏。

## 已核对

- 默认首项为样本 1 / “处理单元 1”，左侧按 fixture 的样本顺序展示第四幕处理单元；它们不是原作场次编号。
- V1 与 V2 阅读区均由 `versions[].fullText` 驱动；V1 有 3 个处理单元，V2 有 4 个 Demo 拆分单元。V2 仅是处理切分，不是曹禺剧本修订。
- V2 版本选择可操作；关系审阅弹层展示三项 fixture 影响，并可将实体关联补入拆分场次或保留既有关联。
- 粘贴文本可在浏览器本地导入；导入后进入“本地导入 · 未上传”，不显示外部来源文本标签，也不自动调用模型。空文本与 12,000 字符上限有明确错误。
- 桌面三栏工作台与底部任务账本没有遮挡。窄屏隐藏版本下拉、保留场次抽屉入口和导入按钮；正文滚动区域无横向裁切。
- 通过真实前端入口按处理单元顺序请求既有 `/api/ai/breakdown`。无 Key 的本地验证明确显示为 `fallback / MISSING_API_KEY`，不会冒充 DeepSeek；每一项展示待审状态、模式、原因和建议数量。
- 点击建议证据会在当前版本的整场原文内按 fixture 的字符范围逐字高亮；证据跨段时仍可定位。范围不匹配时仅显示错误提示，不猜测位置。
- 建议名称可编辑；采用、关联与忽略均改变本地状态。采用后会进入稳定生产实体，显示类型、Metadata 和跨场来源；任务材料只能生成本地“未下发”草稿。
- 1440 × 960 和 390 × 844 截图已保存到 `web/artifacts/raindrama-ui-1440.png` 与 `web/artifacts/raindrama-ui-390.png`。窄屏将分析入口换行显示，避免页面级横向溢出。

## 已知边界

- 窄屏采用分区滚动：脚本正文、建议审阅和任务账本分别在各自区域滚动，完整页面截图不会展开其内部滚动内容。这是既有工作台布局的响应式策略，不影响控件可达性。
- `.txt` 文件选择逻辑仅接受扩展名为 `.txt` 的 UTF-8 文本；不支持、也不尝试读取 PDF、DOCX 或 FDX。
- 当前为一次私下面试 Demo 的《雷雨》第四幕 fixture，不是完整作品或完整幕文本，也不是公开分发素材。
